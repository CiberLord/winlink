# WinLink

PowerShell и файлы Windows с Mac через OpenSSH. Подходит для локального Codex и ручной работы из терминала.

## Первый запуск

Нужны Mac с Node.js 22 или новее и Windows 11 в той же сети Wi‑Fi. На Windows войди в обычную учётку, с файлами которой хочешь работать. Для подтверждения UAC понадобится пароль администратора.

**На Mac**

```bash
git clone https://github.com/CiberLord/winlink.git
cd winlink
npm ci
npm run build
npm link
winlink pair
```

При первом запуске `ssh-keygen` предложит пароль для отдельного ключа WinLink. Если сетевых интерфейсов несколько и WinLink не определил Wi‑Fi, он выведет доступные IPv4-адреса. Перезапусти команду с `winlink pair --ip <IP_Mac>`.

**На Windows** клонируй репозиторий и из его папки выполни команду, которую показал Mac. Например:

```powershell
.\setup.cmd 192.168.1.42
```

Подтверди UAC и сверь код Mac в двух терминалах. Windows подготовит OpenSSH и покажет свой код. Сверь его на Mac и подтверди совпадение там. WinLink сам обменяется публичными ключами, проверит SSH, PowerShell и SFTP и сохранит подключение. Из одного терминала в другой нужно перенести только IP Mac.

Если `npm link` недоступен, используй `node dist/cli.js` вместо `winlink` из папки проекта.

## Команды на Mac

```bash
winlink doctor --json
winlink exec --json 'Get-Location'
winlink ls --json 'C:\Games\Elden Ring\Mods'
winlink get 'C:\Games\Elden Ring\Mods\mod.zip' ./mod.zip
winlink put ./mod.zip 'C:\Games\Elden Ring\Mods\new-mod.zip'
```

Для автоматизации Codex может вызывать эти команды напрямую. `--json` выдаёт один объект с версией формата, результатом или ошибкой. У `exec` в результате есть stdout, stderr, код завершения и признак тайм-аута. Для явного кода завершения PowerShell используй `exit N`.

`get` и `put` передают один файл и завершаются ошибкой, если файл назначения уже существует. Данные сначала записываются во временный файл рядом с назначением. Если сеть оборвалась в момент завершения загрузки на Windows, проверь назначение через `ls` перед повтором. Операции пишутся в `~/.winlink/operations.jsonl` с временем, названием команды и результатом.

## Восстановление

- `winlink doctor` проверяет порт 22, SSH-вход, PowerShell и SFTP. Если ключ защищён паролем и SSH-агент его забыл, загрузи ключ командой `ssh-add ~/.winlink/id_ed25519`.
- На Windows `setup.cmd -Mode Status` показывает состояние службы, порт, правило брандмауэра и события OpenSSH. `setup.cmd -Mode Rollback` возвращает настройки, которые были до первого запуска WinLink.
- Если изменился адрес Mac или Windows, снова запусти `winlink pair` и команду Windows. Служба поднимается после перезагрузки автоматически.
- Если CLI недоступен, используй `ssh -F ~/.winlink/ssh_config winlink-windows` или `sftp -F ~/.winlink/ssh_config winlink-windows`.
- Если компьютеры не видят друг друга, проверь, что они в одной Wi‑Fi сети и на Mac разрешены входящие подключения для Node.js на время привязки. Если Windows запросила перезагрузку во время установки компонента OpenSSH, перезагрузи её и повтори привязку.

## Устройство проекта

`winlink pair` на время привязки слушает порт 48765 на выбранном LAN-адресе Mac. Через него идут публичные ключи и данные подключения. На каждом устройстве пользователь сверяет первые 16 символов SHA‑256-отпечатка чужого ключа с кодом на другом экране. При успешном подключении проверенный ключ Windows сохраняется целиком. Дальнейшие команды и файлы передаются через SSH.

Установщик использует штатный `sshd` и выделяет под WinLink правило брандмауэра для IP Mac. Доступ ограничен подтверждённым ключом Mac и правами выбранной Windows-учётки. Если на ПК уже работает самостоятельно настроенная служба OpenSSH, установщик остановится перед изменением её настроек.

Для будущего доступа через Tailscale или WireGuard понадобится разрешить адрес Mac на VPN-интерфейсе Windows и указать VPN-адрес Windows в SSH-профиле. CLI уже отделяет команды и передачу файлов от параметров SSH-подключения. [OpenSSH через Tailscale](https://tailscale.com/docs/reference/ssh-over-tailscale)
